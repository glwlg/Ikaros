# 智能记账“常规月度预算 + 年度大额专项资金池”双轨预算功能需求设计 (PRD)

## 1. 背景与业务痛点
当前智能记账模块仅支持单一维度的按月预算（`month: YYYY-MM`），在实际家庭财务管理中面临以下痛点：
1. **大额低频开销冲击常规月度预算**：房租（季付）、车险（年缴）、固定车位费（半年/年缴）、大件电器或人情礼金等集中发生时，会导致当月支出严重超标，破坏月度常规消费的参考价值。
2. **缺乏资金“蓄水池”概念**：家庭无法在系统中按月计提储备低频大额资金，缺乏跨月度、全年度的专项开销规划与跟踪视图。
3. **日常与非日常混杂**：日常高频生活开销（买菜、日化、外卖）与周期性刚性支出（房租、车险）缺乏分流机制。

---

## 2. 核心功能目标
构建**“常规月度预算 + 年度大额专项资金池”双轨预算管理体系**：
- **常规月度预算（Monthly Routine Budget）**：聚焦家庭日常高频运转（餐饮、日化、宝宝高频消耗、交通等），考核月度消费节制率。
- **年度大额专项资金池（Annual Large-Expense Pool）**：管理低频、集中性的大额支出（房租、保险、车位、耐用品、医疗准备金等），支持“月度计提蓄水”与“核销追踪”。
- **大额支出分流与识别机制**：支持按预设大额分类或单笔支出标记为“大额专项支出”，避免误计入日常月度预算导致虚假超支预警。

---

## 3. 详细需求规格

### 3.1 数据模型扩展 (Data Model)
在现有预算及记账模型基础上扩展：

#### 1) 预算表 `accounting_budgets` 扩展
- 新增字段 `budget_type`: `VARCHAR(20)`，默认为 `monthly`。
  - `monthly`: 常规月度预算（维持现有 `month: YYYY-MM` 维度）。
  - `annual_pool`: 年度大额专项预算池（按年度维度，如 `year: YYYY`，或 `period_type: annual`）。
- 新增字段 `period_key`: `VARCHAR(10)`，统一标识周期（如 `2026-09` 或 `2026`）。
- 新增字段 `monthly_provision`: `NUMERIC(12, 2)`（仅对 `annual_pool` 生效，表示每月建议计提储备金额，例如 5,000 元/月）。
- 新增字段 `pool_name`: `VARCHAR(50)`（专项池名称，如“年度大额专项池”或具体细项）。

#### 2) 交易记录表 `accounting_records` 扩展
- 新增字段 `is_large_expense`: `BOOLEAN`，默认为 `FALSE`。
  - `TRUE`: 标识该笔支出为年度大额专项支出。
  - 统计月度常规预算消耗时，自动**排除** `is_large_expense = TRUE` 的支出。
  - 统计年度大额专项池核销时，专门汇总 `is_large_expense = TRUE` 的支出。

---

### 3.2 大额专项判定与分流机制 (Classification & Routing)
1. **自动识别规则（智能推荐/规则匹配）**：
   - 类别匹配：预设属于大额专项的分类（如“房租”、“车险”、“车位费”、“大件家电”）。
   - 金额阈值触发：单笔支出超过设定阈值（例如单笔 ≥ 1,500 元），系统自动提示或默认打上 `is_large_expense` 标签。
2. **快捷记账 CLI / Bot / 自然语言解析兼容**：
   - Quick Accounting 在调用入账时，支持参数 `--is-large-expense true/false`。
   - LLM 解析提示词增强：识别到“房租”、“交车险”、“买金锁”、“付车位费”等低频大额词汇时，自动填充 `is_large_expense: true`。
3. **前端手动修正**：
   - 在账单编辑/新增弹窗中，增加 `[ ] 计入年度大额专项池（不占常规月度预算）` 复选开关。

---

### 3.3 预算核算与统计逻辑 (Calculation Logic)

#### 1) 常规月度预算视图
- **月度预算额度**：用户设定的当月常规预算（如 7,800 元）。
- **当月常规已支出**：当月发生的所有支出中，`is_large_expense = FALSE` 的总金额。
- **常规预算结余**：`月度预算额度 - 当月常规已支出`。
- **超支预警**：仅根据常规支出计算百分比（避免因付了 6,600 元房租导致月度进度条瞬间爆表 200%）。

#### 2) 年度大额专项资金池视图
- **年度预算总额**：全年度规划总额度（如 60,000 元）。
- **月度计划计提**：按月建议储备金额（如 5,000 元/月）。
- **当年累计计提蓄水**：`截至当前月份数 × 月度计划计提`（例如 8 月底累计计提 40,000 元）。
- **当年大额实际已核销**：当年发生的所有 `is_large_expense = TRUE` 支出总和。
- **专项池当前可用结余**：`当年累计计提蓄水 - 当年大额实际已核销`。
- **全年额度消耗进度**：`当年大额实际已核销 / 年度预算总额`。

### 3.4 API 接口设计 (API Specification)

1. `GET /api/accounting/budgets`
   - 入参：`book_id`, `period_key` (可选, 如 `2026-09` 或 `2026`), `budget_type` (可选: `monthly` / `annual_pool`)
   - 返回：常规预算列表及专项池配置。
2. `POST /api/accounting/budgets`
   - 保存常规预算或年度专项池参数（支持配置总预算与月度计提额度）。
3. `GET /api/accounting/budgets/dual-track-summary`
   - 入参：`book_id`, `year`, `month`
   - 返回格式：
     ```json
     {
       "month": "2026-09",
       "year": "2026",
       "routine_budget": {
         "budget_amount": 7800.0,
         "spent_amount": 3450.0,
         "remaining_amount": 4350.0,
         "usage_percent": 44.23,
         "categories": [...]
       },
       "annual_pool": {
         "annual_budget_limit": 60000.0,
         "monthly_provision": 5000.0,
         "accumulated_provision": 45000.0,
         "spent_total": 38100.0,
         "current_balance": 6900.0,
         "usage_percent": 63.5,
         "records": [...]
       }
     }
     ```

### 3.5 前端界面交互设计 (UI/UX - BudgetView.vue)

1. **双轨卡片切换/并列展示**：
   - 页面顶部增加两张核心卡片（可切换或平铺）：
     - **卡片 A【日常月度预算】**：环形进度圈，展示当月日常消费进度（7,800 元基准），展示各高频分类消耗。
     - **卡片 B【年度大额专项池】**：蓄水池卡片，显示“月度已计提蓄水”、“已核销大额（房租/车险等）”、“专项池蓄水安全余额”。
2. **大额开销标签标识**：
   - 账单流水列表中，大额专项账单显示淡金色或专属徽标 `[年度大额]`，移入提示“本笔开销已由年度专项资金池核销，不计入月度常规超支”。
3. **配置弹窗支持双模设置**：
   - “常规月度预算设置”：设置月度总预算与分类预算。
   - “年度大额资金池设置”：设置年度规划总额、每月自动计提额度、默认大额触发分类与阈值。

---

## 4. 落地与兼容性考虑
1. **数据平滑迁移**：现有历史记账记录的 `is_large_expense` 默认填 `FALSE`，历史预算默认按 `monthly` 处理，完全向后兼容。
2. **一键历史大额归集**：提供一个批量工具/按钮，可根据分类（房租、保险等）或单笔金额筛选历史记录，一键标记补正为大额专项支出。
3. **测试覆盖**：
   - 包含单元测试：常规月度支出与大额专项支出互斥统计；
   - 边界测试：跨年时大额池结余结转逻辑。
